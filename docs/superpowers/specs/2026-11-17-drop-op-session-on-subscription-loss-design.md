# 購読喪失で op の warm セッションも捨てる

## 意図

Thread 網の組み変わり（router id の一斉振り直し）のあと、照明への op の warm セッションが古いまま残り、次の on が MRP 再送尽きを待ってから再確立していた。実測で on が 15〜36 秒かかった。人感センサー連動の点灯が大きく遅れる主因。

同じノードの購読はその前に無音 deadline で喪失→再確立しており、経路が死んだ兆しは op より先に見えていた。

## 決めたこと

購読ループが「購読が成立して喪失した」とき（`subscription lost; resubscribing`）、そのノードの op 用 warm セッションを `drop_session` で捨てる。次の op は cold establish（実測 0.5〜1 秒）になり、15 秒待ちが消える。

- 対象外: 喪失理由が `touched:`（op 側が新セッションを張った直後）。捨てると張りたての op セッションを壊すため。
- `drop_session` は try_lock なので、実行中 op のセッションは巻き込まない。
- 機器への通信は増えない（捨てるだけ。先回りの再確立はしない）。

## 却下した案

- 照明だけ裏で先に張り直す: 遅れもゼロにできるが、op セッション新設は購読の張り直し（touched）を誘発する。効果を見てから足す。
- 定期プローブ: 約 20 台へ常時トラフィック。得るものに見合わない。

## 限界

網が組み変わってから購読喪失を検知するまで（最大 330 秒）に来た op は従来どおり 15 秒待つ。
